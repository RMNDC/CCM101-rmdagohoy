# Reflection

To begin with, configuring a host-based firewall showed me how vital local defenses are when securing a system. Even if an attacker manages to breach the main network perimeter, a host-based firewall acts as a direct security guard on the server itself. It strictly filters incoming connections so that only safe, approved traffic can interact with the operating system.

Furthermore, managing open ports is critical because every open port acts like an unlocked door or window on a house. By systematically closing unneeded ports, I actively reduce the server's attack surface, which leaves bad actors with far fewer pathways to exploit. For instance, leaving a database port like 3306 exposed to the public internet is extremely dangerous because anyone online can attempt to brute-force passwords or steal sensitive data directly from the system.

Ultimately, completing this lab mission completely shifted my perspective on server security. I realized that servers are never safe by default, and even a small mistake—such as missing a basic firewall rule—can easily allow an intruder to compromise an entire system in seconds.

Looking back, building my GitHub portfolio with eight completed missions gives me a huge sense of accomplishment. Seeing a growing collection of hands-on security projects demonstrates my practical skills and proves how much progress I am making step by step.
