# Laboratory Reflection

## 1. Most Important Cloud Infrastructure Component

For me, **networking** is the most important component because cloud services cannot be accessed without a working network. However, I also learned that compute, storage, and networking depend on each other to keep a cloud system running.

## 2. How Linux Supports Cloud Computing

Linux provides a lightweight and flexible environment for running cloud applications and virtual machines. I experienced this through KillerCoda, where I used Linux commands to inspect the system's CPU, RAM, storage, network, and operating system.

## 3. Why Documentation Matters Before Deploying

Documentation organizes technical information and makes it easier to understand and review. Creating `infrastructure-report.md` and `cloud-components.md` helped me organize my findings and made it possible for others to understand my work.

## 4. New Skills Learned

I learned how to use Linux commands, Git, GitHub, and Markdown for technical work. I also knew now the GitHub authentication, Linux syntax errors, and Git's handling of empty folders.

## 5. How This Improved My Portfolio

Before this laboratory, my repository mainly contained Lab 1. Now it includes a second laboratory folder with Markdown documents, a cloud infrastructure diagram, and screenshots, showing my practical experience with Linux, Git, GitHub, and cloud concepts.
