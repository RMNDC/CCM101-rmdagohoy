# Reflection
To begin with, automation is essential when managing hundreds of cloud servers because manual administration is simply too slow and leads to human error. By using custom Bash scripts and schedulers, engineers can execute repetitive tasks—such as backing up important files—simultaneously across entire fleets of machines. This saves immense time and guarantees that every single server is maintained consistently without needing constant manual supervision.   However, while automation increases efficiency, it also introduces serious potential dangers if a script contains mistakes. A single flawed line of code can automatically break or disrupt hundreds of servers in seconds before anyone notices. Furthermore, because automated scripts often run with administrative privileges, an incorrect command could accidentally wipe out critical data or create security vulnerabilities across the system.   In comparison, writing a Bash script felt very different from creating a Docker Compose file back in Mission 6. Writing a Bash script involves listing step-by-step commands for the Linux terminal to execute sequentially, such as creating folders and compressing directories. On the other hand, a Docker Compose YAML file is declarative, meaning it defines the final layout and configuration of app containers rather than listing line-by-line terminal instructions.   Ultimately, my understanding of Cloud Computing has evolved dramatically from Laboratory 1 through Laboratory 9. At first, I viewed the cloud as just a single distant computer that required manual commands for every task. Now, I understand that real-world cloud infrastructure relies on host-based firewalls, containerized applications, and automated workflows to stay secure, scalable, and reliable.Looking back at all the missions, I enjoyed acting as a Cloud Automation Engineer the most because writing self-running code felt incredibly empowering. Watching my script create directories and generate backup archives automatically showed me how modern tech companies manage large-scale systems. It was truly exciting to combine shell coding with task scheduling to solve real server operational challenges.
